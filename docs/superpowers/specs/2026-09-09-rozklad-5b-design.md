# Розклад 5-Б — дизайн

**Дата:** 2026-09-09
**Статус:** узгоджено, готово до планування реалізації

## Задача

Дитина вчиться в 5-Б за розкладом, що чергується двома тижнями — **синім** і **жовтим**. Розклад нестандартний: замість 45-хвилинних уроків — п'ять **модулів** по 1,5 години, кожен розбитий на три **міні-модулі** по 30 хвилин із перервами.

Через це неможливо тримати в голові дві прості речі:

- о котрій сьогодні починається школа (початок стрибає між 9:55 і 12:00 залежно від тижня);
- який зараз предмет і скільки ще сидіти.

Додаток відповідає рівно на це.

## Користувач і контекст

Одна дитина, 5 клас. Телефон. Відкриває на бігу, однією рукою, часто в коридорі між модулями. Розклад веде батько.

Наслідки для дизайну: mobile-first, без реєстрації, без налаштувань, працює офлайн, головна відповідь видна без прокрутки й без жодного тику.

## Дані — `schedule.json`

Єдине джерело правди. Правиться вручну, зокрема прямо на github.com із телефона.

Нижче — форма файлу; повні дані беруться з таблиць розкладу вище. Для стислості показано один день жовтого тижня.

```json
{
  "meta": { "class": "5-Б", "year": "2026-2027" },

  "modules": {
    "1": [["08:00","08:30"], ["08:35","09:05"], ["09:10","09:40"]],
    "2": [["09:55","10:25"], ["10:30","11:00"], ["11:05","11:35"]],
    "3": [["12:00","12:30"], ["12:35","13:05"], ["13:10","13:40"]],
    "4": [["13:55","14:25"], ["14:30","15:00"], ["15:05","15:35"]],
    "5": [["15:50","16:20"], ["16:25","16:55"], ["17:00","17:30"]]
  },

  "holidays": [
    { "name": "Осінні канікули",  "from": "2026-10-26", "to": "2026-11-01" },
    { "name": "Зимові канікули",  "from": "2026-12-25", "to": "2027-01-10" },
    { "name": "Весняні канікули", "from": "2027-03-22", "to": "2027-03-28" }
  ],

  "weekOverrides": {},

  "schedules": [
    {
      "validFrom": "2026-09-01",
      "anchor": { "weekStart": "2026-09-07", "color": "yellow" },
      "weeks": {
        "yellow": {
          "mon": {
            "2": { "subject": "Українська література",
                   "teachers": [{ "name": "Голінько Ю.А.", "room": "117" }] },
            "3": { "subject": "Математика",
                   "teachers": [{ "name": "Ткаченко А.", "room": "306" }] },
            "4": { "subject": "Англійська мова",
                   "teachers": [{ "name": "Головко Н.О.", "room": "109" },
                                { "name": "Міхно О.Л.",   "room": "108" }] }
          }
        },
        "blue": {}
      }
    }
  ]
}
```

Рішення, закладені у формат:

**Модуль без уроку просто відсутній.** Ключа `"1"` немає ніде — додаток сам виводить, що день починається з другого модуля. Жодних `null`.

**`teachers` завжди масив.** Один вчитель — масив з одного, два — з двох. У коді немає особливого випадку для англійської, у UI — однаковий рендер.

**`schedules` — масив із `validFrom`.** У січні новий розклад **додається** другим елементом зі своєю опорною датою, а не перезаписує старий. Додаток бере той запис, чий `validFrom` найпізніший серед тих, що вже настали. Практичний наслідок: новий розклад можна закомітити в грудні — він увімкнеться сам 11 січня.

**`weekOverrides`** — мапа `"YYYY-MM-DD" (понеділок) → "yellow" | "blue"`. Порожня, поки формула працює. Якщо школа зіб'є чергування — один рядок виправляє конкретний тиждень, решта рахується формулою далі.

## Логіка

Усе — чисті функції, що приймають час явним аргументом. Тому будь-яку дату року можна перевірити тестом, не чекаючи листопада.

```
calendar.js
  weekColorFor(date, data)   → 'yellow' | 'blue'
  holidayFor(date, data)     → { name, from, to } | null
  nextSchoolDay(date, data)  → Date

day.js
  lessonsFor(date, data)     → [{ module, subject, teachers, from, to, miniModules }]

state.js
  stateAt(now, data)         → один зі станів нижче

format.js
  humanMinutes(n)            → «1 хвилина» / «2 хвилини» / «5 хвилин»
```

### Чергування тижнів

`weekColorFor` рахує кількість повних тижнів між понеділком опорної дати й понеділком запитуваної дати. Парне число — колір опорного тижня, непарне — протилежний. Канікулярні тижні **рахуються нарівні з навчальними**. `weekOverrides` перевіряється першим і має пріоритет над формулою.

Опорна дата: тиждень від **07.09.2026 — жовтий**.

### Стани

`stateAt` повертає рівно один стан. UI його просто малює.

| Стан | Коли | Ключове повідомлення |
|---|---|---|
| `lesson` | іде міні-модуль | предмет, кабінети, скільки до перерви |
| `break-inner` | 5 хв між міні-модулями | «Математика триває, той самий кабінет» |
| `break-outer` | 15 або 25 хв між модулями | «Далі: Англійська, каб. 108 і 115» |
| `before-school` | сьогодні є уроки, ще не почались | «Сьогодні початок о 12:00 — Фізкультура» |
| `after-school` | уроки скінчились | «На сьогодні все» + картка «Завтра» |
| `weekend` | субота / неділя | «Вихідні. У понеділок з 12:00» |
| `holiday` | дата в канікулах | «Осінні канікули до 1 листопада» + коли й з чого починається школа |

Розділення перерв на `break-inner` та `break-outer` — навмисне. П'ятихвилинна означає «нікуди не йди, це той самий предмет». П'ятнадцяти- або двадцятип'ятихвилинна означає «збирайся, кабінет інший». Для дитини це протилежні вказівки.

Стан `lesson` і `break-inner` несуть номер поточного міні-модуля та його межі, щоб UI показав розгортку модуля.

### Порядок перевірки станів

Стани перевіряються згори вниз, перший збіг виграє:

1. дата поза семестрами (до 01.09.2026, після 01.06.2027 або в проміжку 25.12 – 10.01) → `holiday`;
2. дата в діапазоні `holidays` → `holiday` — **навіть якщо це субота**;
3. субота або неділя → `weekend`;
4. у розкладі цього дня немає жодного модуля → `after-school` (вироджений випадок, у поточних даних не трапляється);
5. далі — за часом: `before-school`, `lesson`, `break-inner`, `break-outer`, `after-school`.

### Вибір запису `schedules`

Береться запис із найпізнішим `validFrom` серед тих, що вже настали. Якщо дата раніша за перший `validFrom` — береться перший запис. Записи впорядковані за `validFrom`; валідатор у `data.js` це перевіряє й падає гучно, якщо порядок порушено.

### Час і часовий пояс

Час береться локальний із пристрою й порівнюється з рядками виду `"09:55"` як із настінним часом. Перехід на зимовий/літній час тому нічого не ламає — жодної арифметики в UTC.

Сторінка перемальовується раз на 10 секунд, щоб зворотний відлік не застигав.

## Екрани

Дві вкладки: **Сьогодні** і **Тиждень**.

### Сьогодні

Згори — жовта або синя смуга з датою й назвою тижня. Під нею блок «зараз» у кольорі тижня: підпис стану, предмет великим, вчитель і кабінет.

Далі — **вертикальна стрічка дня**: кожен модуль окремим пунктом із часом, назвою, вчителем і кабінетом. Пройдені притлумлені, поточний виділений. Останній пункт — «додому» з часом кінця.

**Поточний модуль розкривається списком** на три міні-модулі й дві перерви з точним часом кожного:

```
9:55 – 11:35   Математика
               каб. 301 · Ткаченко А.
               ├ 9:55   ✓ перший міні-модуль
               ├ 10:25    перерва 5 хв
               ├ 10:30    другий міні-модуль   ← зараз
               │          ▓▓▓▓░░░░░░░░
               ├ 11:00    перерва 5 хв
               └ 11:05    третій міні-модуль
```

Без смуг-загадок: кожен рядок підписаний часом і словами. Прогрес-смужка є тільки в поточного міні-модуля.

Внизу стрічки, одразу після «додому», — **картка «Завтра»**: день тижня, дата, межі дня та перелік предметів. Вона опиняється перед очима саме тоді, коли питання «а що завтра» виникає, — коли сьогоднішній день доскрольовано до кінця. Окремої навігації по днях немає.

### Тиждень

Перемикач **Жовтий / Синій** із позначкою, який із них поточний. Нижче — п'ять карток днів, кожна з повною назвою предметів, часом початку кожного модуля й межами дня. Сьогоднішній день обведений.

Сітку 5×4 відкинуто свідомо: у неї «Моя планета Земля» перетворюється на «Пла-нета». Виграш одного погляду дістається дорослому, який знає предмети напам'ять, а програш — дитині, яка читає.

### Канікули

Заголовок сірий — кольору тижня немає. Великими: назва канікул і до якого числа. Нижче: коли наступний навчальний день, якого він кольору, о котрій і з якого предмета починається.

## Технічний стек

Vanilla ES-модулі, без бандлера й без фреймворку. Vitest тільки для тестів — devDependency, у задеплоєне не потрапляє.

**Задеплоєний додаток має нуль рантайм-залежностей.** Ніщо не зогниє й нічого не треба оновлювати.

Фреймворк не розв'язує жодної проблеми, яка тут є: немає стану, роутингу, мережі. Але логіка дат нетривіальна, і без тестів вона зламається тихо — тому Vitest потрібен.

```
index.html          єдина сторінка
app.css
schedule.json       те, що правиться руками
src/
  data.js       завантаження + валідація JSON
  calendar.js   колір тижня, канікули, наступний навчальний день
  day.js        уроки на дату
  state.js      стан «зараз»            ← ядро
  format.js     відмінки, час
  ui.js         рендер стану в DOM      ← єдине без тестів, свідомо
test/
  calendar.test.js
  day.test.js
  state.test.js
  format.test.js
```

`ui.js` не тестується навмисно: він нічого не вирішує, лише малює готовий об'єкт стану. Уся здатність помилитись живе у файлах, покритих тестами.

## Тести

Конкретні дати, не абстракції:

- `09.09 10:15` → `lesson`, Математика, міні-модуль 1 з 3
- `09.09 10:27` → `break-inner`, Математика триває
- `09.09 10:40` → `lesson`, міні-модуль 2 з 3, минуло 10 із 30 хв
- `09.09 11:45` → `break-outer` (обід 25 хв), далі Англійська, каб. 108 і 115
- `09.09 14:00` → `after-school` (жовта середа кінчається о 13:40), завтра з 12:00
- `07.09 09:00` → `before-school`, старт о 9:55
- `12.09` (субота) → `weekend`
- `14.09` → синій тиждень (перевірка чергування)
- `28.10` → `holiday`, осінні, наступний навчальний день 02.11
- `02.11` → **жовтий** за формулою; окремий тест на те, що `weekOverrides` це перекриває
- `31.10` (субота всередині осінніх канікул) → `holiday`, а не `weekend`
- `15.07.2027` (літо) → `holiday`
- `24.12` та `11.01` → перемикання між записами `schedules`
- останній міні-модуль останнього модуля → «далі нічого, кінець дня»
- «вікно» в розкладі (модулі II і IV без III) → одна довга `break-outer`, без падіння
- відмінки: 1 / 2 / 5 / 11 / 21 хвилина

Помилка «02.11 — синій» була допущена вручну під час дизайну й спіймана калькулятором. Це рівно той клас багів, заради якого тести й існують: виглядає правдоподібно і мовчить.

## Деплой

GitHub Pages з гілки `main`, корінь репозиторію. Ніякого CI, ніякої збірки — Pages віддає файли як є.

Оновлення розкладу: правка `schedule.json` (можна прямо на github.com із телефона) → коміт → за пів хвилини вже в додатку.

`index.html` містить `<link rel="manifest">` та іконку, щоб додаток ставився на домашній екран телефона й відкривався без адресного рядка. Це пакування, а не функція: жодних сповіщень і жодного service worker поки що.

## Поза межами

Свідомо не робимо: домашні завдання, сповіщення, «що взяти з собою», синхронізацію між пристроями, редактор розкладу в UI, підтримку інших класів, темну тему, бекенд, базу даних.

Причина: додаток, який робить одну річ і відкривається миттєво, дитина відкриє. Той, що просить щось вводити, — ні. Усе перелічене можна додати пізніше, не переробляючи ні модель даних, ні екрани.
